# 86. CREACIÓN Y ESTRUCTURA DE PROYECTO EN PHP

La **ESTRUCTURA DE PROYECTO** es la forma en que organizas las carpetas y archivos dentro del código para garantizar que el sistema sea escalable, mantenible y legible.

Dividir el código según su función evita el "código espagueti" y permite que diferentes desarrolladores trabajen sobre distintas partes del proyecto sin interferir entre sí.

La **ESTRUCTURA DE PROYECTO** es el esqueleto que sostiene la arquitectura de tu aplicación.

---

## 86.1. ¿POR QUÉ ES IMPORTANTE UNA BUENA ESTRUCTURA?

Estructurar un proyecto no es solo una cuestión de orden estético; es una necesidad técnica. Una estructura modular garantiza que cada archivo tenga un propósito único y bien definido.

1. **Escalabilidad**: Permite agregar nuevas funcionalidades sin alterar la lógica existente.
2. **Mantenibilidad**: Facilita la localización rápida de errores o componentes que requieren actualización.
3. **Trabajo en equipo**: Define convenciones claras para que múltiples programadores colaboren sin generar conflictos.

---

## 86.2. ORGANIZACIÓN MODULAR EN PHP (httpcrud)

En un desarrollo profesional de PHP, el directorio principal se fragmenta en módulos específicos que agrupan responsabilidades relacionadas.

💡 Ejemplo de Estructura Modular:

a) **business/**: Contiene el "corazón" de la aplicación (casos de uso, servicios y reglas de negocio puras).
b) **exceptions/**: Agrupa las excepciones personalizadas para controlar de forma centralizada los errores del sistema.
c) **validators/**: Contiene las clases encargadas de comprobar que los datos recibidos cumplen con el formato o requisitos esperados.
d) **interfaces/**: Define los contratos que deben cumplir las distintas clases (por ejemplo, los repositorios).

---

## 86.3. SEPARACIÓN DE RESPONSABILIDADES (SOC)

El principio de **SEPARACIÓN DE RESPONSABILIDADES (Separation of Concerns -SOC-)** establece que cada módulo o carpeta debe resolver un aspecto delimitado del sistema.

1. **Capa de Dominio** (business): Maneja la lógica operativa independientemente de la base de datos o de la entrada del usuario.
2. **Capa de Soporte** (validators, exceptions): Ofrece utilidades que protegen la integridad de los datos antes de ejecutar las acciones.
3. **Capa de Persistencia** (data): Maneja el almacenamiento y recuperación de información (repositorios).

---

## 86.4. APLICACIÓN Y RELACIÓN CON LARAVEL

Laravel implementa de forma nativa esta misma filosofía organizativa, traduciendo cada una de estas carpetas en componentes estándar del framework:

| **Concepto en PHP Puro** | **Equivalente en Laravel**    | **Propósito**                                                                         |
| :----------------------- | :---------------------------- | :------------------------------------------------------------------------------------ |
| business/                | App\Services / Action Classes | Lógica de negocio extraída fuera del controlador para evitar Fat Controllers.         |
| exceptions/              | App\Exceptions                | Manejo global y personalizado de errores y excepciones de la aplicación.              |
| interfaces/              | App\Contracts                 | Interfaces que abstraen las implementaciones específicas de servicios o repositorios. |
| validators/              | App\Http\Requests             | Clases Form Request para validar los datos entrantes de las peticiones HTTP.          |

---

## 86.5. COMPONENTES INFRAESTRUCTURALES (index.php, autoload.php y data/)

Además de la lógica modular, el proyecto requiere componentes globales para orquestar la ejecución:

e) **index.php (Punto de Entrada HTTP):** Recibe todas las peticiones, evalúa el verbo HTTP (GET, POST, PUT, DELETE) y ejecuta las respuestas o captura excepciones globales. En Laravel equivale a `public/index.php` y al sistema de rutas.
f) **autoload.php (Carga Automática):** Registra e incluye dinámicamente los archivos de las clases cuando son requeridas. En Laravel y proyectos PHP modernos se gestiona automáticamente mediante Composer (`vendor/autoload.php`).
g) **data/ (Capa de Persistencia):** Almacena las clases encargadas de interactuar con el origen de los datos (Bases de datos / Repositorios). En Laravel esto equivale a la capa de Modelos (`app/Models`) o la capa de Repositorios (`app/Repositories`).

## 86.6. CONCLUSIÓN

Organizar tu proyecto en carpetas especializadas (business, data, exceptions, interfaces, validators) asegura que la infraestructura no interfiera con la lógica principal. Adoptar estas estructuras en PHP puro facilita la transición a frameworks modernos como Laravel, donde estos patrones están integrados por defecto.
