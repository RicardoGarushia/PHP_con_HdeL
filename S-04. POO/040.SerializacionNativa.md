# 40. POO y Web: Serialización Nativa de Objetos en PHP

## 40.1. Introducción a la Serialización Nativa

La **serialización nativa** es el proceso mediante el cual PHP convierte cualquier valor o estructura de datos en memoria (incluyendo instancias de objetos con propiedades `public`, `protected` y `private`) en una cadena de texto formateada según el estándar interno del motor Zend.

A diferencia de **JSON** (que es un formato agnóstico e interoperable), el string generado por `serialize()` conserva el **tipo exacto de la clase** y sus visibilidades, permitiendo reconstruir exactamente la misma instancia al invocar `unserialize()`.

---

## 40.2. Comparativa: Serialización Nativa vs. JSON

| Característica | Serialización Nativa (`serialize`) | Intercambio JSON (`json_encode`) |
| :--- | :--- | :--- |
| **Interoperabilidad** | Uso exclusivo en PHP. | Universal (JavaScript, Python, Go, etc.). |
| **Conservación de Tipos** | Restaura la clase exacta y su tipo. | Convierte objetos a `stdClass` o `array`. |
| **Visibilidad POO** | Incluye `protected` y `private`. | Solo incluye propiedades `public`. |
| **Uso Común** | Caché local, Sesiones (`$_SESSION`), Colas. | APIs REST, Comunicación Cliente-Servidor. |

---

## 40.3. Métodos Mágicos `__serialize()` y `__unserialize()`

Introducidos en PHP 7.4 y consolidados como el estándar en PHP 8.0+, sustituyen a la antigua interfaz `Serializable` y a los métodos `__sleep()` / `__wakeup()`.

```php
public function __serialize(): array
{
    // Retorna un array asociativo con los pares clave/valor que deben guardarse
    return [
        'propiedad_a' => $this->propiedadA,
    ];
}

public function __unserialize(array $data): void
{
    // Reconstruye el estado interno de la instancia con los datos recuperados
    $this->propiedadA = $data['propiedad_a'];
}
```

Ventajas sobre los métodos antiguos:
- Retornan y aceptan arrays simples y limpios.
- Evitan problemas de recursividad e inconsistencia de tipos.
- Se ejecutan automáticamente durante las llamadas a `serialize()` y `unserialize()`.

---

## 40.4. Riesgos de Seguridad e Inyección de Objetos

La deserialización de cadenas provenientes de fuentes no confiables (por ejemplo, entradas de usuario o cookies) representa una vulnerabilidad de alta gravedad conocida como Inyección de Objetos PHP (PHP Object Injection).

Para mitigar este riesgo, `unserialize()` soporta la opción `allowed_classes` en su segundo argumento:

```php
// 1. Permitir solo clases específicas conocidas
$objeto = unserialize($datos, ['allowed_classes' => [MiClase::class]]);

// 2. Deshabilitar completamente la creación de clases (revierte a __PHP_Incomplete_Class)
$objeto = unserialize($datos, ['allowed_classes' => false]);
```
