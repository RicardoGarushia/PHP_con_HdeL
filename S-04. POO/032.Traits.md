# 32. POO: Traits (Rasgos) y Reutilización Horizontal de Código

## 32.1. ¿Qué son los Traits?

Un **Trait** (rasgo) es un mecanismo de reutilización de código diseñado para lenguajes de **herencia simple** como PHP. 

En PHP, una clase solo puede heredar directamente de un padre (`extends`). Esto genera un problema cuando varias clases no relacionadas por jerarquía (es decir, no comparten una relación de tipo *"Es un/a"*) necesitan compartir la misma funcionalidad sin duplicar código.

Los **traits** resuelven esta limitación permitiendo la **composición horizontal de código**: una clase puede importar uno o varios traits mediante la palabra reservada `use`, incrustando sus métodos y propiedades directamente dentro de su propio ámbito.

---

## 32.2. Origen e Historia

El concepto de *Traits* fue formulado en 2003 por los investigadores en POO **Nathanael Schärli, Stéphane Ducasse, Oscar Nierstrasz y Andrew Black**. 

Fue diseñado como una alternativa moderna a la herencia múltiple tradicional con los siguientes objetivos:
1. **Evitar la ambigüedad (Problema del Diamante):** A diferencia de la herencia múltiple clásica (presente en lenguajes como C++), los traits no heredan estado de forma ambigua; son simplemente bloques de código planos que se componen en la clase.
2. **Promover el desacoplamiento:** Permite compartir capacidades o comportamientos específicos sin forzar a las clases a pertenecer a una misma jerarquía rígida.

Fueron implementados por primera vez en *Smalltalk* (2003) e integrados oficialmente en PHP a partir de la versión **PHP 5.4** (2012).

---

## 32.3. Comparativa: Clase vs. Interfaz vs. Trait

| Criterio | Clase | Interfaz | Trait |
| :--- | :--- | :--- | :--- |
| **Propósito Principal** | Definir la entidad y crear objetos. | Definir un contrato de métodos (Qué hacer). | Reutilizar código ejecutable (Cómo hacerlo). |
| **Instanciable (`new`)** | Sí (si no es abstracta). | No. | No. |
| **Contiene Lógica/Cuerpo**| Sí. | No (solo firmas de métodos). | Sí (métodos con implementación). |
| **Herencia/Inclusión** | Herencia simple (`extends`). | Múltiple implementación (`implements`). | Múltiple inclusión horizontal (`use`). |
| **Definición de Estado** | Propiedades, constantes y constructor. | Solo constantes (`const`). | Propiedades, constantes (PHP 8.2+) y métodos. |

---

## 32.4. Sintaxis y Reglas de Visibilidad

La estructura de un Trait es similar a la de una clase, pero utiliza la palabra reservada `trait`.

```php
<?php
trait NombreDelTrait 
{
    // Propiedades
    public string $propiedadPública;
    private int $propiedadPrivada;

    // Métodos con cualquier nivel de visibilidad
    public function metodoPublico(): void {}
    protected function metodoProtegido(): void {}
    private function metodoPrivado(): void {}
}
```

### 32.4.1. Regla Fundamental de Ámbitos y Visibilidad

Cuando una clase utiliza un **Trait** mediante `use NombreDelTrait;`, los miembros (Propiedades y métodos) del **Trait** se comportan **_como si hubieran sido escritos directamente dentro de la clase_**:

- Un método `private` dentro de un Trait solo puede ser invocado internamente por la clase que lo consume (`$this->metodoPrivado()`).
- Un método `protected` estará accesible dentro de la clase y de sus subclases.
- Un método `public` estará disponible tanto interna como externamente desde el objeto.

>
> Es necesario no confundir...
> El uso de `use` **dentro del cuerpo de una clase** que se utiliza para para **incorporar un Trait**. Le dice a PHP que componga los métodos de ese trait horizontalmente dentro de la clase.
> De uso de `use` **a nivel de archivo (fuera de clase)** que se utiliza para **importar Namespaces**. Le dice a PHP que clase o trait de qué carpeta

## 32.5. Ejemplo Práctico (`032.Traits.php`)

```php
<?php
declare(strict_types=1);

header("Content-Type: text/plain; charset=utf-8");

echo "======================================================================\n";
echo "32. POO: Traits (Rasgos) y Reutilización Horizontal de Código\n";
echo "======================================================================\n\n";

// --- TRAITS ---
// Trait #1: Registro Login Cliente
trait RegistroLoginCliente 
{
    public function loginCliente(string $usuario, string $registroAcceso): void 
    {
        if (!file_exists($registroAcceso)) {
            file_put_contents($registroAcceso, "");
        }

        $logAcceso = file_get_contents($registroAcceso);
        $logAcceso .= "{$usuario} se logueó el " . date("Y-m-d H:i:s") . "\n";
        file_put_contents($registroAcceso,$logAcceso);

        echo "[LOG]: Registro de acceso guardado en {$registroAcceso}\n";
    }

    public function registrarCliente(string $usuario): void 
    {
        echo "[REGISTRO]: El cliente {$usuario} se ha registrado.\n";
        $this->loginCliente($usuario, "log_" . $usuario . ".txt");
    }
}

trait EnviarEmail 
{
    protected function enviarEmail(string $nombre): void 
    {
        echo "[EMAIL]: Notificación por correo enviada a {$nombre}\n";
    }
}

trait EnviarTarjetaRegalo 
{
    private const TARJETA_REGALO = 100.0;

    private function enviarTarjetaRegalo(string $nombre): void 
    {
        echo "[REGALO]: Tarjeta enviada a {$nombre} con valor de$" . self::TARJETA_REGALO . "\n";
    }
}

// --- CLASE CONSUMIDORA ---

class Cliente 
{
    private string $usuario;
    private string $contrasena;

    // Composición de múltiples traits
    use EnviarEmail, EnviarTarjetaRegalo, RegistroLoginCliente;

    public function __construct(string $usuario, string$contrasena)
    {
        $this->usuario =$usuario;
        $this->contrasena =$contrasena;

        // Invocación de métodos aportados por los traits
        $this->enviarEmail($this->usuario);         // Protected
        $this->enviarTarjetaRegalo($this->usuario);  // Private
        $this->registrarCliente($this->usuario);    // Public
    }
}

// --- EJECUCIÓN ---

$cliente = new Cliente("Ricardo", "contrasena123");

```

---

## 32.6. Análisis Técnico del Ejemplo

- **Inclusión Múltiple:** La clase Cliente importa tres traits distintos en una sola línea (use EnviarEmail, EnviarTarjetaRegalo, RegistroLoginCliente;). Esto le otorga capacidades de correo, regalos y logging sin necesidad de heredar de tres clases diferentes.
- Encapsulamiento Integrado: El método enviarTarjetaRegalo() en el trait EnviarTarjetaRegalo es private. La clase Cliente puede ejecutarlo dentro de su __construct() mediante $this->enviarTarjetaRegalo(...). Sin embargo, si intentamos llamar a $cliente->enviarTarjetaRegalo("Ricardo") desde fuera de la clase, PHP arrojará un error de visibilidad.
- Constantes en Traits (PHP 8.2+): El trait EnviarTarjetaRegalo define private const TARJETA_REGALO = 100.0;. La constante queda enlazada al ámbito de la clase consumidora y se accede mediante self::TARJETA_REGALO.
