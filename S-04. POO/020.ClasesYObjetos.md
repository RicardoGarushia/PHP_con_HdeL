# 20. POO: Clases e Instancias de Clase (Objetos)

El paradigma de **Programación Orientada a Objetos (POO)** se centra en empaquetar datos (propiedades) y comportamientos (métodos) dentro de unidades llamadas **clases** y **objetos**. Facilita la creación de sistemas modulares, escalables y mantenibles.

La POO se fundamenta en cuatro pilares: **Encapsulamiento**, **Abstracción**, **Herencia** y **Polimorfismo**.

---

## 20.1. Clases y Objetos

### 20.1.1. Definición de Clase

Una **clase** es la plantilla o modelo abstracto que define los atributos y comportamientos que poseerán las entidades creadas a partir de ella.

```php
class NombreDeLaClase {
    // a. Propiedades o atributos:
    // b. Métodos o funciones de clase:
        // b1. Constructor:
        // b2. Destructor:
        // b3. Métodos mágicos:
}
```

### 20.1.2. Definición de Objeto

Un **objeto** es una instancia concreta de una clase creada en memoria mediante la palabra reservada **`new`**.

```php
$objeto = new NombreDeLaClase();
```

---

## 20.2. Propiedades y Métodos

- Propiedades (Atributos): Variables pertenecientes a una clase que almacenan el estado o características del objeto.
- Métodos (Funciones de clase): Funciones definidas dentro de una clase que determinan los comportamientos o acciones del objeto.

### 20.2.1. Métodos Dinámicos vs. Estáticos:

- Dinámicos: Requieren la instancia de un objeto para ser invocados mediante el **operador de objeto (Object Operator)** **`->`**.
- Estáticos: Se invocan directamente desde la clase usando el **operador de resolución de ámbito (Scope Resolution Operator)** **`::`**.

---

## 20.3. Niveles de Visibilidad y Encapsulación

Los modificadores de visibilidad determinan las reglas de acceso a los miembros de una clase:

- **`public`**: Accesible desde cualquier parte del código (ámbito interno, subclases y global). Su uso excesivo en propiedades debilita la encapsulación.
- **`protected`**: Accesible únicamente dentro de la propia clase y por sus subclases heredadas. Es la visibilidad recomendada para miembros que deban compartirse en una jerarquía de herencia.
- **`private`**: Accesible estrictamente dentro de la clase que lo declara. Fortalece al máximo la encapsulación, protegiendo la lógica interna y evitando mutaciones no controladas desde el exterior o desde clases hijas.

---

## 20.4. Acceso Directo vs. Acceso Indirecto

- **Acceso Directo**: Ocurre al utilizar el operador de objeto (**`->`**) directamente sobre la propiedad o método sin intermediarios, siempre que el ámbito actual tenga permisos (ej. **`$this->propiedad`** en ámbito interno o **`$objeto->propiedadPublica`** en el ámbito global).
- **Acceso Indirecto**: Se realiza utilizando un método intermediario con visibilidad **`public`** (como un getter o setter) para inspeccionar o modificar miembros **`private`** o **`protected`** a los que el ámbito externo no puede acceder de manera directa.

---

## 20.5. Importancia de Getters, Setters y Métodos Envolventes (Wrappers)

El uso de Getters, Setters y métodos públicos envolventes es una buena práctica fundamental vinculada al principio de Encapsulación:

- Validación de Datos: Permiten validar reglas de negocio antes de asignar valores (ej. evitar precios negativos o correos inválidos en un setter).
- Control de Modificación (Solo lectura / escritura): Puedes exponer solo un getter para crear propiedades de solo lectura sin permitir mutaciones externas.
- Mantenibilidad y Refactorización: Si la estructura interna o el cálculo de una propiedad cambia, la interfaz pública (**`getNombre()`**) permanece intacta, evitando romper el código externo que depende de la clase.
- Ocultamiento de la Complejidad (Abstracción): Invocar métodos **`private`** a través de un método **`public`** orquestador evita que el cliente ejecute procedimientos internos en un orden incorrecto o evite validaciones de seguridad.
